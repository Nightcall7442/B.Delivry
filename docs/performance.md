# Слабый интернет и слабый телефон

Покупатель на базаре сидит на мобильной сети в подвале рынка, у продавца за прилавком старый
Android. Всё, что ниже, сделано под это. Цифры — замеры на локальной сборке, экран 390 px.

## Что сделано

| Что                                                                          | Было                                           | Стало                                                 |
| ---------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------- |
| Ответы API (список прилавков, каталог)                                       | 36–41 КБ JSON                                  | 6–7 КБ (gzip/brotli)                                  |
| Опрос заказов у продавца каждые 6 с (2–3 списка до 100 заказов)              | весь список каждый раз                         | `304` без тела, пока ничего не изменилось             |
| Фото плитки товара                                                           | оригинал 1024 px, 210 КБ                       | WebP 500 px, 34 КБ                                    |
| Аватар продавца                                                              | 210 КБ                                         | 12 КБ (WebP 250 px)                                   |
| Главная сайта, первый экран (фото)                                           | 2,2 МБ                                         | 0,6 МБ                                                |
| Главная сайта, вся страница (фото)                                           | 4,8 МБ                                         | 1,7 МБ                                                |
| Простые страницы сайта («Правила», «Документы», «Цены»…), JS первой загрузки | 450 КБ                                         | 173 КБ (карта грузится только там, где она есть)      |
| `/promo` на медленной сети (экономия трафика, 3G и хуже)                     | 19 МБ кадров и полоса «Открываем ряд» до конца | ~0,8 МБ у начала, остальное по мере прокрутки         |
| Повторный заход: фото, кадры, шрифты, фоны                                   | `max-age=0`, запрос на каждый файл             | неделя в кеше                                         |
| Запрос завис                                                                 | крутится бесконечно                            | 12 с (чтение) / 30 с (запись), чтение пробует ещё раз |

## Как это устроено

- **API** (`apps/api/src/middleware/response-size.middleware.ts`): каждый JSON-ответ на GET получает
  `ETag` (хеш тела) и `Cache-Control: private, no-cache`; запрос с `If-None-Match` получает `304`.
  Тело сжимается (`@fastify/compress`, brotli качества 4 / gzip 6, от 1 КБ).
- **Клиент** (`packages/api-client`): помнит последний ответ на каждый GET (до 48 ответов и
  ~1,5 МБ текста — память слабого телефона считаем) и подставляет его на `304`. Копия не может
  устареть: тег — хеш тела, сервер отвечает `304`, только если ответ тот же. Запись (POST/PATCH…)
  никогда не отправляется повторно сама: первая могла дойти, заказ нельзя оформить дважды.
- **Фото** (`photo(url, width)` в `@bazar/storefront`): для наших файлов отдаёт копии
  `photos/w250|w500|w960/<имя>.webp`; шаг 1280 тоже берёт `w960` (оригиналы 1024 px, резче не
  бывает). В приложении `Photo` сам выбирает копию по размеру рамки (плотность экрана — не выше 2×).
  Копии лежат в репозитории; **добавили фото в `apps/web/public/photos` — запустите
  `pnpm --filter @bazar/web photos`** и закоммитьте результат. Тест в `@bazar/storefront`
  упадёт, если у какого-то фото нет копии.
- **Сайт**: карта (maplibre, ~280 КБ) — отдельный чанк (`components/map/lazy-map.tsx`); плитки
  товаров — `<img srcset loading="lazy">`, а не CSS-фон (фон грузится, даже если плитка далеко за
  экраном); статика из `public/` кешируется на неделю (`next.config.ts`).
- **`/promo`**: если включена экономия трафика или соединение 3G и хуже
  (`navigator.connection`), плёнка грузит только кадры у места, где читатель, и снимает заставку
  после первых.

## Чего здесь нет (и стоит помнить)

- Замеры — не на живых телефонах и не по настоящей медленной сети; цифры по байтам точные, по
  времени — оценка.
- Главная сайта и приложения читают «первые 100» товаров и прилавков. При настоящем каталоге
  нужна постраничная подгрузка.
- Приложение при старте дважды запрашивает прилавки (для точки по умолчанию и для сохранённого
  адреса): ~5 КБ, не исправлялось.
